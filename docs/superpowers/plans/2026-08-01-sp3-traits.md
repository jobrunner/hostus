# hostus 2.0 — SP3 Traits + Fuzzy-Match Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Ingest the three trait vocabularies (EIVE 1.0, Tichý 2023, Midolo 2023) via a name-string crosswalk against the WCVP backbone, serve `GET /v1/concept/{id}/traits`, add fuzzy matching to `POST /v1/match`, and fold in the SP1/SP2 tracked debt (classification hierarchy, basionym, homotypic, bundle self-refs).

**Architecture:** Per-dataset pipelines (`pipelines/<vocab>/build.sh`, the ortus/§4.4 pattern) absorb upstream xlsx chaos and emit ONE canonical CSV per vocabulary; hostus only ever ingests the canonical form (no xlsx dependency in Go). A trait ingest use case resolves each trait row's free-text taxon name to a concept via the existing canonical-fold match machinery, writes `trait_value` rows keyed by `(concept, vocab, vocab_version, dim)`, and reports unmatched names explicitly. Traits are served per vocabulary; the two namespaces (EIVE↔Euro+Med-aligned vs Tichý/Midolo↔FloraVeg/EUNIS-aligned) stay separate per PoC P10 — never merged.

**Tech Stack:** Go 1.26.5, modernc.org/sqlite, the SP1/SP2 hexagonal layers. Pipelines: bash + python3/openpyxl (already in the nix devshell, used by PoC P6) — build-time only, not a service dependency.

## Task 1: Trait domain types (pure)

**Files:** Create `internal/domain/trait.go`, `internal/domain/trait_test.go`

**Interfaces (Produces):**
- `type TraitDim string` + constants: `DimM, DimN, DimR, DimL, DimT` (moisture/nutrients/reaction/light/temperature), `DimS` (salinity, Tichý only), `DimDisturbanceSeverity, DimDisturbanceFrequency, DimMowingFrequency, DimGrazingPressure, DimSoilDisturbance` (Midolo). `ParseTraitDim(string) (TraitDim, error)`.
- `type TraitVocab string` + `VocabEIVE = "eive"`, `VocabTichy = "tichy2023"`, `VocabMidolo = "midolo2023"`; `ParseTraitVocab(string) (TraitVocab, error)`.
- `type TraitValue struct { Vocab TraitVocab; VocabVersion string; Dim TraitDim; Value float64; NicheWidth *float64; NSystems *int }` — pointers because niche width is EIVE-only and `n` is vocab-specific; a nil pointer means "not provided by this vocabulary", NOT zero.
- `type TraitSet struct { Vocab TraitVocab; VocabVersion string; Taxonomy string; Values []TraitValue }` — `Taxonomy` records the namespace (`euromed-aligned` / `floraveg-eunis-aligned`) so callers can never silently merge namespaces (P10).
- `ScaleFor(v TraitVocab, d TraitDim) (min, max float64, normalized bool)` — EIVE M/N/R/L/T → (0,10,true); Tichý L/T/M/R/N → (1,9,false); Tichý S → the range recorded by the pipeline (accept it as data, so return `normalized=false` and a documented default); Midolo dims → unbounded continuous → `(0,0,false)` with a `normalized=false` meaning "no fixed scale". Document precisely; this exists so the API can tell a client that 4.2 EIVE ≠ 4.2 Tichý.
