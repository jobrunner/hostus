# hostus 2.0 — SP4 Xref-Anreicherung Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Enrich the concept index with cross-references to the other taxonomic authorities — above all the **iNaturalist taxon_id that UC2 depends on** — via an **ID-based** join, and measure honestly how much of the backbone is actually reachable.

**The design idea:** we already hold exactly one usable outbound key: `powo` (440,534 xrefs, one per concept; the WCVP `dynamicproperties.powoid`, which *is* the IPNI id). Wikidata carries POWO (P5037) and IPNI (P961) alongside GBIF (P846 legacy / P14607 new), COL (P10585), Euro+Med (P12380), FloraVeg (P12100), WFO (P7715) **and iNaturalist (P3151)**. So Wikidata is used as a **bridge hub**: join our concepts to Wikidata items by POWO/IPNI id, then read every other authority off the same item. Unlike SP3's trait crosswalk this is an identifier join, not a name join — but its **coverage is unknown and measuring it is the point of this milestone.**

**Tech Stack:** the SP0–SP3 stack; a new bulk pipeline (Wikidata Query Service SPARQL, paged) following the established `pipelines/*/build.sh` → canonical CSV pattern.

## Global Constraints

- Builds on `feature/p95-investigation` (which carries SP0–SP3 + reality-check + hardening).
- **Run everything FOREGROUND with bounded timeouts. No monitors, no background-and-poll** — eight agents stalled that way in this project; several had to be rescued.
- **Never read from the repository while an ingest transaction is open** (`SetMaxOpenConns(1)` → real deadlock, cost SP3 an escalation). Resolve first, then write.
- Per-task DoD: tests pass → `make mutation PKG=<pkg>` zero new unjustified survivors → `make lint` clean incl `_test.go` → `make verify` green. Measurement steps: **a number you did not measure is not a number you may report.**
- Never commit bulk data. Docs German. `redistribution` must be set for any new source (Wikidata is CC0 → `allowed`; iNat *taxa* are CC0-ish but **observation** data carries per-observer licences — we only ingest taxon ids here, state it).
- **PoC ground truth (do not re-derive):**
  - **P7:** P846 (GBIF legacy) and P10585 (COL) resolve and cross-validate against the GBIF ids from P3. **P14607 (new GBIF) and P12380 (Euro+Med) were NOT yet populated** on the reference items → query **both** P14607 and P846 and prefer the new one when present. Corrections: *Jacobaea vulgaris* = **Q15630491** (not the value in the source doc), WFO = **P7715**.
  - **P9:** iNat obscures protected taxa to ~**26–28 km** (not the doc's 20 km); ~32–38 % of a protected taxon's records are obscured, 62.6 % usable. Real fields: `taxon_geoprivacy`, `geoprivacy`, `obscured` (**not** `coordinates_obscured`, which does not exist), `public_positional_accuracy`. `quality_grade=research` means two community agreements, **not** expert verification.

- **UC2 requirement (spec §UC2):** `xrefs.inat` must point at the iNat taxon_id of the **accepted** taxon, never a synonym's. Our concepts are already accepted-keyed (synonyms group under them), so this must be preserved, not re-derived.

## Task 1: Wikidata bulk pipeline

**Files:** `pipelines/wikidata/build.sh` (+ a query file and converter), `pipelines/README.md`

**Produce:** a canonical xref CSV, pipe-delimited like the other canonical artifacts:
`join_authority|join_id|authority|ext_id|wikidata_qid`
— one row per (Wikidata item × external authority). `join_authority`/`join_id` is the key we can match on (`powo`/`ipni`), repeated per row so the ingest never has to re-derive it.

- Query the **Wikidata Query Service** (`https://query.wikidata.org/sparql`, `format=json`, proper User-Agent, polite paging — WDQS enforces a 60 s query timeout, so **page by something stable** such as QID ranges or `LIMIT/OFFSET` over an ordered result, and be prepared to split the query; a single unpaged "all plant taxa" query WILL time out).
- Scope it: items that are taxa (P31→Q16521) **and** carry P5037 or P961 (otherwise we can't join them). Harvest per item: P5037 (POWO), P961 (IPNI), **P14607 (GBIF new)**, **P846 (GBIF legacy)**, P10585 (COL), P12380 (Euro+Med), P12100 (FloraVeg), P7715 (WFO), **P3151 (iNaturalist)**.
- Print the usual summary: rows, distinct items, and **a per-authority populated count** — that count is the first real evidence of how sparse each property is (P7 saw P14607/P12380 empty on two reference items; now we get the population-level picture).
- Record the licence (Wikidata is **CC0**) and `redistribution: allowed`.

- [ ] **Step 1:** write the query + `build.sh`; run it against the real WDQS. If a single query can't complete, split and say how.
- [ ] **Step 2:** verify the two reference items appear with the expected values (Q159953 → POWO 396681-1; Q15630491 → IPNI 226649-1).
- [ ] **Step 3:** document the canonical xref-CSV contract in `pipelines/README.md`.
- [ ] **Step 4: commit** `feat(pipelines): Wikidata xref bulk harvest`.

## Task 2: Xref ingest (ID-based join) + coverage measurement

**Files:** `internal/application/xref_ingest.go` (+ tests), `internal/adapters/xref/reader.go` (+ tests + fixture), manifest support, `internal/app` wiring, `cmd/hostus/ingest.go`

**Interfaces:**
- `xref.Read(path) (*Dataset, error)` mirroring the traits reader (pipe CSV, collected errors, never panics).
- `application.IngestXrefs(ctx, repo, src XrefRowSource, meta XrefSourceMeta) (XrefIngestReport, error)` — application-level DTO bridge (depguard: application must not import adapters).
- Resolution is **ID-based**: look up our concept by the row's `join_authority`/`join_id` against the existing `xref` table (`powo`) — add a repository method if needed, e.g. `ConceptIDByXref(ctx, authority, extID)` or a batched variant; **two-phase** (resolve all, then write).
- `XrefIngestReport{ Source string; Rows, Matched, Unmatched, Conflicting int; PerAuthority map[string]int; UnmatchedSample []string }`. **Conflicting** matters: `xref`'s PK is `(authority, ext_id)`, so the same external id claiming two different concepts must be **detected and reported, never silently overwritten** — decide the rule (skip + report is the safe default) and document it.
- `dataset.yaml` gains an `xref_sources:` section (id, version, licence, source, path, `redistribution`), schema-validated like the others.

**Measurement (the point of this task):** after ingesting against the full real DB, report **coverage**: how many of the 440,534 concepts gain at least one new xref; per authority, how many concepts are reachable; and specifically **how many concepts get an iNat id** — that number is UC2's ceiling. Also report conflicts.

## Self-Review Notes
- The join is by identifier, so unlike SP3 there is no normalisation question — the risk here is **coverage** (how many concepts Wikidata actually knows) and **conflicts** (one external id claiming two concepts). Both are measured, not assumed.
- P7's finding that P14607 was unpopulated is handled by querying both GBIF properties; the pipeline's per-authority counts will show whether that has changed at population scale.
- iNat *observation* data is deliberately out of scope — we ingest taxon ids only, so no per-observer licensing question arises. The P9 caveats belong in the UC2 documentation, not in the index.
