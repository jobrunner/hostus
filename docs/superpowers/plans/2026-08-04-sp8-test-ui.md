# hostus 2.0 — SP8 Eingebettete Test-SPA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Serve a small single-page test UI from the Go binary at `/`, switchable off via configuration and a CLI flag, **default on** — so the system can actually be judged by hand instead of through curl.

**Why this exists (owner, 2026-08-04):** *"Mit REST allein macht das keinen [Sinn]."* The autosuggest rework is deliberately blocked on being able to see it. Two measured defects are waiting to be looked at rather than read about: only **9 of 30** top-10 suggest hits begin with the typed prefix (`ca` returns *Kunzea capitata* at position 1), and **0 genera** appear in 30 slots. This UI is the instrument for that judgement, not a product surface.

**Architecture:** assets embedded with `embed.FS` — one self-contained binary, no build step, no `node_modules`, no CDN. Vanilla HTML/CSS/JS. The service is offline-first by design (UC1 is field use with an offline bundle); a UI that needs the network would contradict that.

**Tech Stack:** Go stdlib `embed` + `net/http` on the existing `gorilla/mux` router. **No new Go dependency and no new frontend dependency.**

## Global Constraints

- Branch `feature/sp8-test-ui`, forked from `master` (`578401b`).
- **Run everything FOREGROUND with bounded timeouts. No monitors, no background-and-poll** — eight agents have stalled that way in this project.
- The runtime allowed-libraries list in `CLAUDE.md` is exhaustive. `embed` and `net/http` are stdlib, so nothing new is added. **No JS framework, no bundler, no CDN reference** — `make arch` and `make licenses` must stay green.
- Hexagonal + depguard: the UI is an **adapter** (`internal/adapters/ui` or inside `internal/adapters/http`). It must not reach into `internal/application` or `internal/domain` — it talks to the same public HTTP API a browser client would.
- Per-task DoD, all FOREGROUND: `go test -timeout 180s ./...` → `make mutation PKG=<each touched pkg>` (the gate enforces `Not covered: 0` and a positive mutant floor) → `make lint` clean **including `_test.go`**, both build-tag passes → `make verify` → `make test-integration` → `make security-check` → `make licenses` → `mkdocs --strict`.
- **LSP diagnostics in this repo are frequently STALE.** Trust only `nix develop -c go build ./...` and `go vet ./...`. If `make mutation` hits a permission error: `chmod -R u+w ./.go && rm -rf ./.go`, retry.
- Docs German; code comments sparse and English. Never commit bulk data. Never read, print, or modify `.envrc.local`. Do not touch `VERSION`; CHANGELOG under `[Unreleased]`.
- A real full index for hands-on checking is at `/tmp/full-real.sqlite` — **open read-only**; `sqlite.Open` applies migrations, so copy it if you need a writable one and delete the copy.

### Configuration contract — get this exactly right

The project specifies a strict three-tier ladder (`config.yaml` → `HOSTUS_`-prefixed env → CLI flag) and viper maps a dotted key to an env var by upper-casing and replacing `.` with `_`. So:

- key **`ui.enabled`**, default **`true`** → env var **`HOSTUS_UI_ENABLED`**, CLI flag on `serve`.
- **Do not invent an abbreviation.** `HOSTUS_PORT` is silently ignored today precisely because the key is `server.port`; `docs/reference/configuration.md` documents the rule. Follow it, do not add an alias.
- Add the entry to `config.yaml.example` and `example.env` with an inline English description, as those files' conventions require.

Build the switch before the thing it switches, so the off-path is pinned from the start rather than retrofitted.

## Task 2: The embedded SPA (TDD for the handler, hand-checked for the page)

**Files:** `internal/adapters/ui/` (`embed.go`, `assets/index.html`, `assets/app.js`, `assets/style.css`), handler + tests

**Serving rules:**
- Assets embedded via `embed.FS`. Correct `Content-Type` per extension; `ETag` or `Last-Modified` so a reload is cheap.
- `/` serves the page. An unknown path that is **not** under `/v1`, `/health`, `/metrics` or `/openapi` also serves the page (SPA deep links). An unknown path **under** those prefixes keeps its existing 404 — the API contract must not change shape because a UI exists.
- **A `Content-Security-Policy` that forbids external origins** (`default-src 'self'`). No inline handlers, no `eval`. This is both a security property and the offline guarantee: a page that cannot reach a CDN cannot silently depend on one.
- No caching of API responses — the point is to observe live behaviour.

**The page must exercise what has to be judged**, in one screen:
1. **Suggest** — a search box calling `GET /v1/suggest` as you type. Show for each hit: canonical name, **rank**, whether it is accepted, and `in_area`. Make the two known defects *visible*: mark hits that do **not** begin with the typed prefix, and show the rank mix of the result list. A tester must be able to see the problem without counting by hand. Optional `area` input (note: `?area=` takes a **single** code today — multi-area exists only in `hostus bundle`).
2. **Concept view** — click a hit → `GET /v1/concept/{id}`: names, classification, synonyms, xrefs (all authorities, remembering `xrefs` is `{authority: [ids…]}`), plus `GET /v1/concept/{id}/traits` and `GET /v1/concept/{id}/synonyms?relevance=publication`.
3. **Match** — a textarea of verbatim names → `POST /v1/match`, showing the classification and `requires_review` per line.
4. **Translate** — `POST /v1/translate` from the shown concept into a `sec.` space. **Expect it to answer empty for WCVP concepts** — that is the measured, correct behaviour; the UI must render "keine Relation erfasst" as a *statement*, never as an error or an empty box.

German UI text. Plain, legible, no design ambition — this is an instrument.

## Self-Review Notes

- **Task 1 before Task 2 on purpose:** the off-path is the one nobody exercises, and it is the one an operator relies on. Building it first means it is tested rather than asserted.
- **The UI must make the defects visible, not hide them.** Its whole purpose is judging suggest quality; a page that presents a tidy list would defeat it. Marking non-prefix hits is a deliberate instrument, not decoration.
- **Offline is a property, not a preference.** UC1 is field use with an offline bundle. A CDN reference would be a silent contradiction, which is why the CSP forbids it structurally rather than by convention.
- **Default on, and say so out loud in the docs.** A test console that ships enabled is a deliberate choice for a locally-run, unauthenticated research service — and it is exactly the kind of default that deserves an explicit line in the how-to rather than a quiet one in a struct.
